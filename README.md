# StudentMind

Двуязычный (қазақша / русский) сайт психологической поддержки студентов Казахстана: темы, тесты самооценки,
упражнения, статьи, личный кабинет и админ-панель. Next.js 16 (App Router), TypeScript, Tailwind 4, next-intl,
Supabase (Auth, PostgreSQL, RLS), Recharts.

> Сайт не ставит диагнозов и не заменяет психолога. Тексты, тесты и контакты помощи в репозитории — **демо-версия**:
> перед запуском их должны проверить психолог и носитель казахского языка (см. «Перед запуском»).

## Быстрый старт (демо-режим, без бэкенда)

```bash
npm install
npm run dev          # http://localhost:3000
```

Без настроек Supabase сайт работает полностью, кроме аккаунтов и админ-панели: тесты, упражнения, статьи, поиск,
«Срочная помощь», настроение, дневник, планировщик и прогресс хранятся в браузере этого устройства.

## Подключение Supabase (аккаунты, админ-панель, синхронизация)

1. Создайте проект на supabase.com **или** поднимите локально (нужен Docker): `npx supabase start`.
2. Примените схему и демо-контент:
   - облако: SQL Editor → выполните `supabase/migrations/20261022000001_init.sql`, затем `supabase/seed.sql`;
   - локально: `npx supabase db reset` (применит миграцию и seed).
3. Скопируйте `.env.example` в `.env.local` и заполните:
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` — Project Settings → API;
   - `APP_ENCRYPTION_KEYS` — ключ шифрования дневника и ответов тестов:
     `node -e "console.log('v1:'+require('crypto').randomBytes(32).toString('base64'))"`.
     Сохраните его в надёжном месте: без него зашифрованные записи не прочитать.
4. В Supabase: Authentication → URL Configuration: Site URL = адрес сайта, Redirect URLs += `https://ваш-домен/auth/callback`.
   Для входа через Google включите провайдер Google (Authentication → Providers). Подтверждение email включите
   (в `supabase/config.toml` для локального стека оно уже включено). Лимиты запросов и CAPTCHA на регистрации —
   Authentication → Rate Limits / Attack Protection.
5. Первый администратор: зарегистрируйтесь на сайте, затем в SQL Editor:
   `update public.profiles set role = 'admin' where id = (select id from auth.users where email = 'вы@пример.kz');`
   Дальше роли редактора и администратора выдаются в `/admin/users`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` / `build` / `start` | разработка / сборка / запуск сборки |
| `npm run test` | 61 тест: RLS (PGlite — настоящий Postgres в WASM, Docker не нужен), подсчёт баллов, контент, переводы kk/ru, контраст WCAG AA, шифрование, seed |
| `npm run lint`, `npm run typecheck` | проверки кода |
| `npm run seed:generate` | пересобрать `supabase/seed.sql` из `src/content` |
| `npm run icons` | пересоздать иконки PWA и превью |

## Структура

- `src/content/` — демо-контент (темы, тесты, упражнения, статьи, контакты, политика). Источник для `seed.sql` и демо-режима.
- `messages/kk.json`, `messages/ru.json` — весь интерфейс; тест следит, чтобы ключи совпадали.
- `src/lib/content/` — загрузка контента из Supabase с запасным вариантом из `src/content`; `lib/tests/scoring.ts` — подсчёт результатов (одна функция в браузере и на сервере).
- `src/lib/personal/` — личные данные: `local-store` (гость) и `remote-store` (студент); дневник и ответы тестов шифруются на сервере (`lib/crypto.ts`).
- `src/lib/admin/`, `src/app/[locale]/admin/` — админ-панель (контент на двух языках, тесты с вопросами и порогами уровней, контакты помощи с датой проверки, роли).
- `supabase/migrations/` — схема, RLS, функции. Пользователь видит только свои записи; у администратора нет доступа к личным записям.
- `public/sw.js` — офлайн: дыхание и «Срочная помощь» работают без сети после первого открытия.

## Деплой (Vercel)

Импортируйте репозиторий, добавьте переменные из `.env.example` (`NEXT_PUBLIC_SITE_URL` — боевой адрес), задеплойте.
Заголовки безопасности и CSP настроены в `next.config.ts` (при подключении аналитики добавьте её домен через `NEXT_PUBLIC_ANALYTICS_SRC`).

## Перед запуском: что проверить вручную

- [ ] **Контакты помощи.** Позвоните по каждому номеру, добавьте телефоны доверия и службу вашего вуза в `/admin/contacts`, отметьте «проверен». Встроены только 112 и 111 и помечены как непроверенные. Проверять раз в квартал (админка подсвечивает просроченные).
- [ ] **Психолог** проверил тексты тем и статей, вопросы и пороги уровней всех тестов, формулировки чувствительных вопросов; его имя и квалификация добавлены на «О проекте» (`messages/*.json → about`).
- [ ] **Казахский язык**: вычитка носителем (все тексты написаны как черновик).
- [ ] **Статьи** сейчас по 300–400 слов; в ТЗ — 600–1200. Расширить.
- [ ] **Политика конфиденциальности** проверена юристом (закон РК о персональных данных, место хранения серверов, порядок для несовершеннолетних); затем `LEGAL_REVIEWED = true` в `src/lib/constants.ts`.
- [ ] **Лицензии**: тесты написаны заново и помечены «ориентировочными»; если подключаете лицензионные опросники, проверьте права.
- [ ] Регистрация, вход через Google, письмо подтверждения, сброс пароля, удаление аккаунта — пройти на боевом Supabase.
- [ ] Права: войти двумя разными аккаунтами и убедиться, что данные не пересекаются (автотесты RLS это покрывают, но проверьте на своём проекте).
- [ ] Lighthouse (мобильный режим) на главной; проверка на iPhone (Safari) и Android (Chrome) на экране 360 px.
- [ ] Резервные копии БД (Supabase → Database → Backups), мониторинг ошибок (Sentry не подключён: если добавите, не отправляйте содержимое дневника и ответов тестов).

## Известные ограничения

- Мониторинг ошибок (Sentry), напоминания «Как ты сегодня?», форма обратной связи и CAPTCHA в коде не реализованы (P2 по ТЗ). Аналитика — через переменные `NEXT_PUBLIC_ANALYTICS_*`.
- Регистрация, вход и админ-панель проверены автотестами только на уровне БД (RLS, функции) и валидации форм; сквозные сценарии с живым Supabase нужно пройти вручную.
